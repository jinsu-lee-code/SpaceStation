## 7-1. 동물 주민 (11-11d, `BlenderWork/Animal/animal_builder.py`)
- **둥근 조각(타원체 · 관)을 겹쳐 한 메시로** 만든다 — 조각끼리 잇지 않아 이음선 문제가 없다. 조각마다 바깥 방향은 부호 있는 부피로 정한다(`orient_outward`). 검사: 열린 · 비다양체 가장자리 0.
- **음영은 부드럽게(분할 1.5배)**. 면이 보이는 평면 음영은 "네모네모"해 정거장 키트의 둥근 패널과 결이 달랐다 (사용자 결정, 비교용 `ANIMAL_SHADE=flat`).
- **팔 · 다리는 꺾인 한 관으로** (`limb`). 위 · 아래 두 관을 겹치면 부드러운 음영에서 팔꿈치 · 무릎에 지그재그 선이 보였다.
- **몸에 그리는 무늬(배 · 얼굴 판 · 판다 눈 무늬)는 겹친 타원체가 아니라 표면을 따라 붙인 얇은 판**으로 (`surface_patch`, 겉 +2.5mm · 속 −3mm · 옆띠로 닫음). 타원체를 얕게 겹치면 테두리가 톱니처럼 보였다.
- 귀처럼 기울여 붙이는 파츠는 좌우 부호를 확인한다 (기울기 부호가 반대면 두 귀가 교차). 옆을 보게 돌린 원반 귀는 옆에서 납작한 판처럼 보인다 → 앞을 보게.
- 앞으로 뻗는 관(부리)은 관 기준축이 진행 방향과 나란해지지 않게 다른 기준축을 쓴다.
- **재질 슬롯은 이름으로 찾는다** (`M_Animal_<슬롯>`): Unity가 쓰지 않는 슬롯을 빼서 재질 순서가 종류마다 다르다.
- **코드로 움직일 파츠(귀 · 꼬리 · 눈)는 사람형 22본 밖에 본을 덧붙인다** (11-16, `EXTRA`). 가중치는 뿌리에서 끝으로 갈수록 부모 → 본(`W_soft`) — 통째로 본에 붙이면 돌릴 때 머리 · 엉덩이 속에 묻힌 뿌리가 겉으로 튀어나온다. 눈은 통째로(깜빡임 = 위 축으로 납작하게). 귀가 없는 종류(펭귄)는 본도 없다 → Unity 코드는 본이 없어도 동작하게.
  - **긴 꼬리(고양이 · 강아지 · 여우)는 섞는 폭을 첫 마디 길이만큼 (0.12)**: 0.05로 짧게 섞었더니 앉은 꼬리를 크게 들 때 뿌리 5cm가 접혀 "뚝 끊어진 막대"처럼 보였음 (사용자 2026-10-29). 본 하나짜리 꼬리는 돌린 각이 섞는 폭에 퍼지므로 넓게 섞을수록 휘어 보임. 다시 뽑을 때: `blender -b --factory-startup -P BlenderWork/Animal/animal_builder.py -- <종류> <Assets/…/SM_Animal_<종류>.fbx>` (꼭짓점 수가 그대로인지 확인).
  - 꼬리 · 귀를 코드로 크게 돌릴 때는 큰 머리(반지름 약 0.2)에 닿지 않는지 본다 — 앉은 꼬리를 세웠더니 뒤통수를 뚫었음 → `ResidentSeatFit`이 머리 타원체에 들어가는 각은 고르지 않고 옆으로 기울여 비킴.

## 7-2. 손에 드는 소품 (11-12 휴대 패드)
- **월드 캔버스 UI는 URP 겹침(Overlay) 카메라로 그리지 않는다** — 패드 모델은 보였지만 캔버스 UI가 그려지지 않았음. 본 카메라로 그리고, 벽에 묻히지 않게 눈에서 몸 충돌 반지름(0.3m) 안에 둔다.
- 1인칭 소품 위치는 시야각으로 확인한다 (세로 60°면 0.25m 앞에서 화면 위아래 ±0.144m — 처음 든 자세 y −0.15는 화면 아래로 빠졌음).
- 확인 렌더는 `Unity_Camera_Capture`가 카메라 쌓기 · 자세를 제대로 반영하지 않을 수 있음 → 플레이 중 `Camera.Render()`를 RenderTexture로 받아 PNG로 저장해서 본다.
- **플레이 중에 스크립트를 고치지 않는다** — 다시 컴파일되며 직렬화되지 않는 런타임 참조가 null이 되어 엉뚱한 오류(NullReference)가 났음.

## 7-3. 홀로그램 모형 (11-13 패드 위 모듈 모형)
- 모듈 FBX는 Read/Write가 꺼져 있어 **게임 중에 메시(정점)를 읽을 수 없다** → 외곽선 · 합친 메시는 에디터에서 구워 에셋으로 둔다(`Wire Pad` → `PadHoloSet`). 렌더링만 하는 건 읽기 불가 메시도 된다.
- 눈높이 근처의 **수평 모형은 납작한 판으로 보인다** → 보는 사람 쪽으로 기울인다(55°).
- 가산 재질은 밝은 배경에서 하얗게 타서 색이 사라진다 → 선은 반투명 섞기, 면만 가산 + 뒤에 어두운 배경판. HDR 세기는 1.4 안팎.
- 여러 층 모듈은 아래층에서 시작하면 모형 바닥 밑으로 삐져나온다 → 지금 층 바닥에 앉힌다.
- 고르기는 모듈 상자 대신 **바닥 칸**으로 (큰 모듈 상자가 뒤 작은 모듈을 가림).
- 모형 위 글자(TextMeshPro 3D)는 모형 재질보다 **렌더 큐를 뒤로**(3100) — 같은 투명 큐면 가산 모형이 글자 위에 덧칠돼 묻혔음. 어두운 바탕판도 함께.
- **작은 글자가 많은 화면에서는 뒤 장식을 움직이지 않는다** (11-16 피드백): 글자 뒤로 주사선이 흐르면 가로줄이 글자를 지나가며 글자가 일렁여 보였고, 바탕이 가끔 35%까지 어두워지는 깜박임 · 패널 안을 지나가는 빛줄기도 Bloom 번짐을 흔들어 같은 느낌을 줬음 → 패드는 주사선 정지(`HoloFx.ScanSpeed = 0`) · 깜박임 0.25배(`HoloFx.Flicker`) · 패널 빛줄기 끔(`HoloUi.PanelLine`). ~~부드러운 스캔 띠는 괜찮음~~ → **아니었음 (재발, 2026-10-11)**: 패드를 가만히 두고 두 프레임을 비교하니 HoloFx를 끄면 차이 0, 스캔 띠만 150px 옮겨도 글자 테두리 전체가 바뀜 → 패드는 띠를 내용이 바뀔 때만 한 번(`HoloFx.IdleSweep = false`), 바탕 깜박임 0. 그래도 글자가 **일그러져(크기 · 기준선이 글자마다 들쭉날쭉)** 보였던 진짜 원인은 **내부 공간 위치 y −5000의 float 정밀도** — 정점 위치가 0.5mm 단위로 끊겨 높이 4mm 글자가 12%씩 어긋났고, 패드가 조금만 움직여도 끊기는 자리가 바뀌어 일렁였음 (같은 장면을 플레이어만 원점 근처로 옮겨 찍으니 고르게 나옴) → 내부 원점 y −400(0.03mm), 내부 카메라 시야 거리 250 · 바깥 창 카메라 300으로 서로 안 보이게. **작은 물체 · 글자를 원점에서 수천 m 떨어진 곳에 두지 않는다.** **일렁임은 눈으로 추측하지 말고 정지 화면 두 장의 픽셀 차이로 원인 요소를 하나씩 끄며 찾는다.**
- 손에 든 소품의 화면 · 유리 재질은 무광(매끄러움 0.1 안팎) — 위에 얹은 UI가 잠깐 투명해지면 뒤의 반짝이는 면이 조명을 반사해 번쩍였음. UI 화면 전체 알파를 크게 내리는 연출도 피한다.
- 깜박임 · 번쩍임 같은 짧은 현상은 일시정지(`EditorApplication.isPaused`) 후 `EditorApplication.Step()`으로 한 프레임씩 넘기며 캡처 · 밝기 측정해 원인을 찾는다 (MCP가 프레임 사이에 실시간으로 볼 수 없음).
- **홀로그램 고리 · 눈금은 `MeshTopology.Lines`(1px 선)로 그리지 않는다** (11-16 피드백 "허술해 보임"): 계단이 지고 굵기가 없음 → 안 · 바깥 가장자리 알파 0인 얇은 삼각형 띠(`PadHologram.Band`)로. 둥근 판에 정사각형 칸 범위를 맞추면 모서리가 판 밖으로 나가므로 **축소 한계는 가장 먼 칸까지의 반지름**으로 정한다.
- 손에 드는 소품도 "그 물건만의 특징" 2~3개를 넣는다: 패드 = 두 톤(밝은 뒤판 · 어두운 베젤) · ㄱ자 모서리 가드 + 나사 · 기능과 이어지는 부품(홀로그램이 나오는 자리에 투사기 렌즈). 둥근 판 4개를 모서리에 붙인 첫 버전은 장난감처럼 보였음.
- 화면에 쓰는 기호는 글꼴(Maplestory)에 있는지 확인 — "◢"은 없어서 네모로 나왔음 (▲▼는 있음). **빼기는 하이픈 "-"만** — 수학 빼기 기호 "−"(U+2212)는 없어서 연구 포인트 할인 "−20%"가 네모로 나왔음 (11-17). "·" "×" "→"는 있음. **줄표 "—"(U+2014)도 없음** — 사고 알림이 네모로 나왔음(11-17 ④) → "·". 확인: `TMP_FontAsset.HasCharacter`. **테스트 `FontCoverageTests`가 스크립트 문자열(주석 · Tooltip 제외) · Data 에셋 글자를 두 글꼴 원본에서 조회해 없는 글자가 있으면 실패** — 실행 중 네모는 콘솔 경고 "was not found in the [Maplestory SDF]"로도 찾을 수 있음.

## 7-4. 벽에 붙는 상태 소품 (11-17 파손 지점, `BlenderWork/InteriorProps/damage_builder.py`)
- **연출(연기 · 스파크)에는 그 원인이 보이는 물건을 붙인다** (사용자 피드백): 방 가운데서 연기만 나면 납득되지 않음 → 뜯긴 패널 · 터진 배관 · 불탄 배전함에서 나오게.
- 좌표: 벽면 = Blender xz 평면, 방 쪽 = Blender −y (Unity +z). Unity에서 `LookRotation(벽 법선)`으로 붙인다. 뒷면은 벽에서 1~3mm 띄우고 겹마다 깊이를 다르게(같은 평면 금지).
- 그을음 · 얼룩은 한 장짜리 진한 판이면 각진 검은 판처럼 보임 → 옅은 · 중간 · 진한 세 겹(가장자리일수록 옅게).
- 회전시켜 꺾는 조각(매달린 덮개)은 **회전 중심을 경첩에** — 조각 자기 끝을 중심으로 돌려 벽 속으로 0.12m 들어갔음 (검사의 깊이 최소값이 음수면 의심).
- **파손 방은 붉은 비상 조명뿐이라 어둡다** → 소품마다 작은 불빛(0.5m 앞 · 위). **세기 0.9도 눈이 아플 만큼 셌음(사용자 피드백)** → 0.2~0.3 · 범위 2.4 · 잔잔한 출렁임(꺼졌다 켜지는 깜박임 금지), 스파크 순간 빛도 1.2 이하. 캡처에서 포화(밝기 0.9 이상) 픽셀 0을 확인. 소품 바로 앞에 두면 하얗게 탐. 김 · 연기 입자도 밝은 색이면 근처 불빛 · Bloom에 하얗게 번쩍임.
- 붙일 자리는 실행 중 광선으로 고른다(`InteriorSpots.Walls`): 수직 · 평평(가로 ±0.32 · 세로 ±0.28 네 점) · 앞 0.4m 빈 곳 · 문/유리/해치/주민 제외. 모듈 원점 씨앗으로 섞어 다시 만들어도 같은 자리.
- **광선은 충돌체만 본다 — 보이는 면과 충돌 면이 다른 곳을 조심.** 문 자리 키트 패널(막힌 벽 `KIT_Wall` · 문 `KIT_WallDoor`)은 충돌체가 없고 벽면(Solid)보다 방 안쪽으로 튀어나와, 벽 광선이 맞은 자리에 붙인 환풍구가 패널 뒤에 가려졌음(11-17 ③) → 키트 패널 범위(+0.2) 안은 뺀다. 새 소품 자리는 캡처로 실제로 보이는지 확인.
- **움직이는 덮개 · 뚜껑은 따로 오브젝트로 내보내고 원점을 축(나사 · 경첩)에** 둔다 (환풍구 `VentCover`). Unity에서는 부모 축(벽 법선 = +z) 기준으로 돌린다 — 자식 자기 축은 가져오기 회전이 섞일 수 있음.

- **색으로 종류를 나누는 소품은 그 부분만 흰색 재질 슬롯으로** 따로 둔다(`M_CrateBand` · `M_CaseSeal`) → Unity가 재질 이름으로 찾아 `SetPropertyBlock(block, 재질 번호)`로 물들임. 모델은 하나, 재질 복사 없음.
- 한 면에 붙는 판(라벨 · 잠금쇠 · 봉인)은 **앞(Blender −y) 쪽 깊이를 음수로** — 처음에 +로 넣어 뒷면에 붙었음. 미리보기에서 앞면 부품이 보이는지 확인.

## 7-5. 식물 (11-17, `BlenderWork/InteriorProps/plant_builder.py` · farm_builder `leaf_u`)
- **잎 덩어리(찌그러뜨린 구)로 끝내지 않는다** — 단순해 보였음(사용자 피드백). 잎 한 장 = 잎맥이 솟은 마름모 단면을 잎 길이 따라 쓸어 만든 닫힌 얇은 판(폭은 밑 · 끝이 좁게, 끝으로 갈수록 아래로 휨, 가장자리가 살짝 내려가 오목). 잎자루 · 가지는 가늘어지는 관. 잎마다 닫힌 덩어리라 열린 · 비다양체 0.
- 잎 배치: 황금각(2.4 라디안) 나선, 바깥 잎은 늙고 크고 눕고, 안쪽 잎은 어리고 섬. 색 2~3가지를 섞음(단색이면 돌처럼 보임).
- **상태가 바뀌는 식물(시듦 · 물 주기)은 템플릿에 합치지 않고 따로 놓는 소품**으로 (템플릿 = 화분 · 화단만, 자리는 `InteriorTemplate.PlantSpots`). 시든 모델은 같은 함수에 처짐 · 누런 색 · 떨어진 잎을 더해 따로 내보낸다.
- 벽 가까운 화분은 잎 폭을 재서 벽을 뚫지 않게 크기를 줄인다(회전 링 안쪽 벽 0.45m → 0.7배).
- 템플릿에서 재질 슬롯이 바뀌면(잎 재질 제거) **Build Templates로 프리팹을 다시 만든다** — 안 그러면 남은 재질이 마지막 서브메시에 덧그려짐. Build Templates는 모든 프리팹 ID를 새로 매기고 공용 재질 값을 바꿀 수 있으니 관계없는 파일은 되돌린다.

## 7-6. 움직이는 계층 모델 (12-3b 합성 기계팔 · 고리, `BlenderWork/SynthArm/arm_builder.py`)
- **관절 계층이 있는 FBX는 `bake_space_transform=False`로 내보내고 Unity `ModelImporter.bakeAxisConversion = true`로 축을 맞춘다.** `True`로 내보냈더니 자식 관절의 위치 · 회전이 엉켜 들어왔음(윗팔이 90° 돌아 있고 원점이 어긋남). 결과: 루트만 축 변환 회전, 관절은 모두 회전 0.
- 관절마다 오브젝트를 나누고 **원점을 관절 축에** 둔다. Unity IK는 모델 루트 로컬 축(위 = Blender z, 앞 = Blender +y)을 기준으로 계산 — Blender 미리보기에도 같은 IK를 넣어 토치 끝이 목표에 닿는지(오차 0) 먼저 확인한다.
- 조립해 쓰는 토막(고리 직선 · 모서리)은 이음 끝을 0.002씩 넘겨 겹친다 (끝면 같은 평면 · 맞닿는 틈 방지, 3 · 4).
- 미리보기에서 발광 세기가 크면 하얗게 날아가 색이 안 보인다 (보라 3.0 → 0.9). 실제 세기는 Unity 재질 · 블룸에서 정한다.
- 우주에 떠 있는 장치는 받침 · 기둥으로 "바닥"에 세우지 않는다 (사용자 피드백: 허공에 뿌리박은 기둥처럼 보임) → 대상에 붙거나 스스로 뜨는 형태(추진 노즐 · 반중력 원반 · 틈)로.
