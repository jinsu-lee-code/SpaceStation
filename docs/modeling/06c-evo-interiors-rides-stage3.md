# 모델링 06c — 진화 모듈 내부 템플릿 ③ 2단계 나머지 · 탈것 · 3단계 (정련 콤비나트 · 실드 돔 · 요새 포대 · 차폐벽 · 드론 정비창 · 후룸 · 회전목마 · 미로 · 궤도 도시 · 바이오스피어)

> 원래 `MODELING.md` 7-11절 뒷부분 (363 ~ 410줄)을 그대로 옮김 (2026-11-11 분할). 06b의 "2단계 개방형 방" 하위 목록이 이어짐 (3단계 항목도 이 목록 안에 있음). 매번 확인할 항목은 [00-checklist.md](00-checklist.md).

  - **탈것 앞면은 한 덩어리로** (사용자 정련 콤비나트 채굴선 "전면부의 위아래가 달라 어색한점"): 유리 공과 어두운 공을 겹치면 위아래가 다른 물체처럼 보임 → 코는 몸통 단면에서 이어지는 이음새 없는 모양 (`nose_loft`, 둥근 사각 → 타원), 유리 조종석은 코 위에 따로 얹고 금빛 띠로 둘레를 이음
  - **칸 위로 솟는 외형을 1층 내부로 (정련 콤비나트)**: 내부는 칸 위 경계 (3.95) 안이어야 함 → 단 · 돔 높이를 줄이고 반지름은 유지하면 실루엣이 그대로 읽힘 (돔 꼭대기 외형 5.7 → 내부 5.2m, 하늘 껍데기 y1 = 3.95). 낮은 돔 벽을 지나는 문은 구멍만 뚫으면 머리가 닿음: 아치 높이에서 돔 반지름까지 짧은 굴 (현관)로, 유리는 같은 아치로 잘라냄
  - **볼트 안 크레인 · 들보는 움직이는 전 범위의 꼭짓점 반지름을 잰다**: 볼트 고리 안쪽 반지름보다 작아야 지나갈 때 고리를 뚫지 않음 (레일을 낮추고 바퀴를 줄여 최대 2.15 / 고리 2.2). 레일은 고리까지 닿게, 문 아치 꼭대기는 레일 밑으로. 줄 · 집게 · 손가락 피벗 구조는 `InteriorScrapCrane`과 같음
  - **압력 막을 큰 아치에 쓸 때 재질을 따로** (`SpaceStation/PressureVeil`): `_Arch` 기본값이 문 크기 (반폭 1.02)라, 반지름 2.2 아치에 그대로 쓰면 반폭 밖 전체가 테두리로 빛나 불투명한 크림색 벽이 됨 → `M_InteriorEvo2Membrane` (`_Arch` = 실제 반폭 · 시작 높이, `_Veil` 0.22). 바깥 면에 둔 빛 창은 벽을 관통시키지 말 것 (안에서 큰 흰 덩어리로 보임)
  - **빛나는 천체 = 플라즈마 셰이더** (`SpaceStation/Plasma`, `M_InteriorEvo2Sun`): 단색 발광 공 대신 잡음 무늬. **홍염은 메시로 만들지 않음** (사용자 "태양의 고리가 뚫고 지나가는점. 고정되어있는점."): 굳은 관은 표면을 뚫은 것처럼 보이고 움직임이 없음 → `InteriorSunForge`가 LineRenderer + `SolarFlare` (가산 · 끝과 가장자리가 흐림 · 흐르는 빛 결)로 표면 아무 데서나 솟았다 사라지게. `Mathf.Pow`에 `Sin(π)`를 넣으면 아주 작은 음수라 NaN → LineRenderer 범위 전체가 NaN이 되어 통째로 안 그려짐 (사진으로 확인할 것, 위치 기록만으로는 못 잡음). `InteriorPlasma`는 처음 만들 때만 값을 넣으므로 색을 바꾸면 재질 값도 직접 고칠 것
  - **열린 lathe는 축까지 막힌다 (실드 돔)**: `lathe`는 프로필을 반지름 0까지 닫아 바닥이 막힌 덩어리를 만듦. 등대 안을 지나는 전망대 받침을 `lathe`로 만들었더니 계단 위로 안 보이는 천장이 생겨 3층 높이에서 못 올라감 (시안 사진에서는 어두운 계단 윗부분처럼 보였음). 속이 빈 탑 둘레의 고리는 `lathe_loop` + 안쪽 반지름. 계단 · 탑을 만들면 축 근처에서 위로 쏘아 맞는 면을 확인할 것
  - **나선 계단 머리 공간은 층계참 끝에서 잰다**: 계단 한 바퀴 높이 − 층계참 두께 − 키 (캡슐 위 끝 1.83m)만 보면 모자람. 캡슐이 축 쪽으로 붙으면 각도 폭 δ = asin(0.3 / r)가 커져, 앞쪽 발은 높은 단에 얹히고 뒤쪽 머리는 층계참 끝 밑에 걸림 (내려올 때 특히). 대책 = 한 바퀴를 높이고 (2.86m), 층계참을 얇게 (6cm), 기둥 쪽 층계참을 짧게 깎기. 시험은 r = 0.5 · 0.8 · 1.15 세 바퀴를 **올라갔다 내려와야** 함 (올라가기만 하면 통과하기도 함). 캐릭터 컨트롤러 stepOffset 0.3이라 단 높이 12cm는 문제없음
  - **휜 유리에 낸 평평한 문은 문틀 깊이를 유리까지 뺀다**: 아치 양 끝에서는 원통 유리가 문 면보다 안쪽으로 들어감 (반지름 1.55, 반폭 0.74 → 19cm). 문틀 깊이가 모자라면 옆으로 틈이 생기고 사진에는 잘 안 보임 → 틈 검사 (유리 · 막도 흰 판, 하늘 끔)로 찾음. 압력 막 반지름은 문틀 안쪽 반지름보다 약간 크게
  - **비스듬한 몸통의 띠는 위 · 아래 가장자리를 몸통 반지름에 맞춘다**: 한 줄 안에서 같은 반지름을 쓰면 아래쪽에서 몸통 면이 띠를 뚫어 톱니처럼 보임. 띠는 끊기지 않는 나선 하나로 만들어 위아래 끝을 받침 · 코벨 속에 숨김 (끊긴 끝이 뒤쪽에서 보이지 않게)
  - **문 굴의 같은 면 겹침**: 안쪽 반지름이 같은 아치 띠 둘 (테 · 벽)이 겹치면 맞닿는 구간이 들쭉날쭉 깜빡임. 겹치는 쪽 안쪽 반지름을 6mm 작게. 원형 바닥 판과 굴 바닥 판은 원 안쪽까지 겹쳐 놓을 것 (끝을 원 접선에 맞추면 양 옆에 쐐기 틈)
  - **내부 오로라 (`AuroraFx` unit = 8, `M_InteriorEvo2Aurora`)**: 바깥 호를 그대로 쓰되 띠 간격 · 빛살 · 주름을 8배로. 아랫단은 전망대 눈높이 근처에 둘 것 — 낮으면 난간에 섰을 때 시야 전체가 초록으로 덮임. 하늘 벽 안 (등대에서 벽까지 7.15m)에 들어오게 반지름을 줄임. 등대 빛은 렌즈 자식으로 둔 `LightBeamFx` (렌즈와 함께 돎, 재질 `M_InteriorEvo2BeaconBeam`)
  - **칸 위로 큰 연출은 하늘 화면에 (요새 포대 불꽃)**: 내부 칸은 천장까지 5m뿐이라 불꽃을 안에 띄울 수 없음. 개방형 방의 하늘은 실제 바깥 카메라 화면이고 바깥 × 8 = 내부 좌표라, 바깥 모델의 `FireworkFx`를 그대로 보이면 내부 대롱 위로 올라가 10 ~ 13m 높이에서 터짐 (`InteriorExteriorView`가 `Firework_` 입자는 숨기지 않음, 별자리 면은 그 화면 카메라를 봄). 내부 쪽은 대롱 불티와 연병장 번쩍임만. 하늘 화면을 찍으려면 주 카메라를 그 자리로 옮길 것 (사진용 카메라만 옮기면 하늘은 주 카메라 자세로 그려짐)
  - **머리 높이를 지나는 장식은 충돌 없는 조각으로**: 깃발 줄을 Shell에 합쳤더니 성벽 위 길에서 머리가 줄에 걸려 멈춤 → 별도 `Bunting` (Shell · Glass만 충돌). 돌아다니는 길 위를 지나는 줄 · 전구 · 깃발은 모두 같음
  - **계단 아래 끝은 옆에서 올라설 수 있어야 함**: 갑판 가장자리 난간 바로 앞에서 시작한 계단은 양옆 난간에 막혀 들어갈 수 없었음 → 아래에 평지를 두고 난간은 첫 단부터. 판 폭이 좁으면 단 깊이를 줄임 (0.27 → 0.21, 40°)
  - **난간 틈은 토막 단위가 아니라 잘라서**: 토막 가운데로 틈을 판단하면 틈에 걸친 토막 끝이 길을 막음 (`rail_path`가 틈 안을 잘라냄)
  - **문 앞 길을 평면도에서 잰다**: 현관 양옆에 관람석을 붙였더니 사이가 55cm라 정문에 갈 수 없었음 (시안 사진에는 안 보임) → 걷기 시험에서 정문까지 실제로 걸을 것
  - **주민 쉬는 자리는 맨 아랫줄만**: 계단식 관람석 위 줄에 앉히면 일어날 때 아래 줄 위에 서서 그 높이로 걸어 나감. `ResidentWander`는 이제 높이가 같은 자리로만 감 (난간에 붙은 자리는 처음 닿은 난간이 길 검사에서 빠져, 성벽 위 → 갑판으로 공중을 걸어갔음)
  - **잘라낸 면이 맞닿으면 안 보이는 얇은 벽이 남음 (방사선 차폐벽 부두 계단)**: 불리언 상자 둘을 같은 평면에서 맞대면 (z = 1.81) 그 면이 두께 없는 한쪽 면 판으로 남아, 눈에는 안 보이는데 충돌체가 길을 막음 (위에서 내려 쏜 광선도 못 잡음, 옆에서 쏴야 잡힘) → 자르는 상자는 서로 겹치게. 걷기 시험에서 "난간도 없는데 막힘"이면 이것부터 의심
  - **난간 다각형은 닫힘이 기본**: `rail_path`에 `closed=False`를 안 주면 마지막 변이 처음으로 이어져, 강 쪽 벽 위로 난간이 하나 더 생겨 부두 입구를 막음. 시안 사진에서는 어색하지 않아 놓치기 쉬움 → 입구는 걷기 시험으로 확인
  - **새 재질 값은 만든 뒤 파일에서 확인**: 셰이더에 프로퍼티를 추가한 직후 `CreateMaterials`로 만든 재질에 `SetFloat` 값이 안 들어가 있었음 (원인 미확인, `_CoordScale`이 기본값 1로 남아 은하수가 8배 작고 거칠게 보임). 사진이 이상하면 `.mat` 값부터 볼 것
  - **바깥 크기 셰이더를 안으로 가져올 때**: 물체 공간 좌표로 그리는 셰이더 (`MilkyRiver`)는 `_CoordScale` = 1/8로 그대로 쓸 수 있지만, 멀리서 보던 별은 가까이에서 눈송이처럼 커 보임 → 별 크기 · 밀도를 따로 줄임 (`_StarSize` 0.38 · `_StarDensity` 0.6). 물가 무늬처럼 바깥 모델 숫자가 박힌 값도 프로퍼티로 뺌
  - **이름이 겹치는 재질 슬롯**: `Evo2Sun`은 이미 정련 콤비나트 해 (주황 플라즈마). 새 재질을 만들기 전에 `InteriorTemplateBuilder` 재질 표에서 이름을 찾아볼 것 (병풍 해 · 표지 = `Evo2Lemon`). 큰 면에 `Accent`를 쓰면 발광이라 번쩍임 → 큰 면은 `Paint`
  - **큰 둥근 문의 압력 막은 옅은 재질**: 지름 3m 달문에 기본 `Evo2Curtain`을 쓰면 안이 안 보이고 희게 뜸 → `Evo2Membrane` (정련 콤비나트 격납고와 같음). 작은 아치는 `Evo2Curtain` 그대로
  - **발광 구 바로 아래에 점광원을 두지 말 것**: 달 등 밑 3cm에 조명을 두니 아랫면이 작은 해처럼 번쩍임 → 조명을 40cm 내리고 등 재질 광택을 0.12로
  - **자리 수 = 들어오는 주민 수**: 쉬는 · 서는 자리를 44개 두었더니 43명이 들어와 길을 막음 (좁은 길에서 플레이어가 멈춤) → 5칸 모듈 25자리. 플레이어가 앉는 자리 (`InteriorBenchSeats`)는 따로라 벤치는 많이 둬도 됨
  - **앉기 · 내리기 컴포넌트는 실행 순서 -320**: F는 `InteriorMode`(-300)가 앉히는데, 앉은 채 F를 읽는 컴포넌트가 그보다 늦게 돌면 같은 프레임에 바로 일어남 (요새 포대 관람석 · 차폐벽 벤치, 코드 검토에서 발견). **`Completed()`를 직접 부르는 시험은 이 경로를 못 잡음** — 키 입력 경로로 시험하거나, 안 되면 못 했다고 보고할 것
  - **해치 도착점은 뚜껑 중심 + 바라보는 쪽 1.1m**: 개방형 방에서 난간 가까이 두면 밖으로 나갈 수 있었음 → `UseHatch`가 앞이 막히면 덜 감. 그래도 뚜껑 ±0.7 · 틀 ±0.95가 난간 · 벤치와 겹치지 않는 자리에 둘 것
  - **벽감 전시물은 벽까지 거리를 재서 크기를 정함**: 지그재그 벽감은 안쪽으로 갈수록 좁아, 시안 사진에는 안 보여도 고리가 벽 · 설명판을 뚫음  - **난간은 경계가 아님**: 허리 높이 난간은 벤치 (비비면 0.44m도 올라섬) · 앉은 주민 위 (발 1.17m) · 등받이를 밟고 넘어갈 수 있었음 → 개방형 방은 칸 경계에 보이지 않는 벽 (`InteriorBuilder.OpenAirBarrier`, 문 자리만 뚫림), 주민에게 머리 위까지 기둥 (`NoClimb`, Ignore Raycast), 그래도 3초 넘게 떨어지면 있던 방 입구로. 설명판 · 표지처럼 틀 안에 그리는 그림은 별 크기까지 더해 틀 안에 드는지 계산할 것
