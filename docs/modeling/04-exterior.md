# 모델링 04 — 바깥 모듈 외형 · 진화 모듈 외형 · 단계별 테마

> 원래 `MODELING.md` 7-7절 (155 ~ 173줄) · 7-9 ~ 7-10절 (220 ~ 282줄)을 그대로 옮김 (2026-11-11 분할). 매번 확인할 항목은 [00-checklist.md](00-checklist.md).

## 7-7. 바깥 모듈 외형 (12-5, `BlenderWork/Modules_Work.blend` 텍스트 블록 `newbasic_builder`)
- **글꼴로 만든 글자(평면 `flat_char` · 곡면 `text_on_cylinder`)는 덮개 방향을 따로 맞춘다** (`fix_caps`). 글꼴 메시는 앞뒤 덮개와 옆벽이 서로 떨어진 조각이라 키트의 법선 재계산(`_add`)이 납작한 덮개 방향을 정하지 못해, 앞뒤 덮개가 모두 한쪽을 봤다 → 상업 구역 간판 뒷면 'SHOP'이 Unity에서 속이 빈 윤곽선으로 보였음(바깥 덮개가 판 쪽을 봐 뒷면 컬링). `fix_caps(오브젝트, 재질, 축)` = 위치 열쇠로 덩어리를 나눠 덮개마다 두께 가운데에서 바깥쪽을 보게.
  - **Blender 미리보기는 뒷면도 그려서 이 문제가 안 보인다.** 양면에서 보이는 부품(간판 · 표지판)은 Unity에서 앞뒤를 모두 렌더해 확인한다.
- **회전(`rot`)으로 기울인 상자는 법선 재계산에서 통째로 뒤집혀 나올 수 있다** (상업 구역 차양 줄무늬 40칸 중 1칸). 빌드 끝에 `orient_parts(몸체)` = 위치 열쇠(반올림 1e-5)로 이은 덩어리마다 부호 있는 부피가 음수면 면을 뒤집음. **점을 합쳐서(remove_doubles) 판정하지 않는다** — 몸체는 색 굽기 UV 이음매가 있어 점을 합치면 굽기가 깨진다.
- 맞닿는 네온 테두리 막대(가로 · 세로)는 끝점이 정확히 만나면 점 병합에서 비다양체가 된다 → 가로 막대를 세로 막대 밖까지 늘리고 두께도 엇갈림 (3번과 같은 규칙).
- 검사(내보내기 전): 몸체 · 부품마다 열린 가장자리 · 비다양체 가장자리 · 뒤집힌 덩어리 0.
- **Unity 적용은 그 모듈 하나만** (`StripGreybox` 같은 단계 + `StationArtBuilder.RebuildModule(id)`). 메뉴 Apply New Basic Models는 모델이 있는 모든 새 모듈을 다시 조립하고, 조립기가 모든 모듈 프리팹의 선택 콜라이더(`Pick`)를 다시 만들어 ID가 바뀌며 진화 모듈 프리팹에는 `Pick`이 잔뜩 생겼음 → 그 모듈 외 프리팹 변경은 되돌린다. 모듈 데이터의 `_faceDepths`(새 모델 기준 통로 연결 깊이) 변경은 남긴다.
- 봇 측정이 에디터에서 도는 중이면 플레이 모드 대신 편집 모드에서 프리팹을 잠시 놓고 URP 카메라(후처리 켬)로 렌더해 확인한다 (플레이 모드 진입 시 측정이 끊길 수 있음).
- 공통 자산이라 `main` · `tycoon` 양쪽에 같게: 모델 · 텍스처 · 재질 · 프리팹은 커밋 변경분을 패치로, `Modules_Work.blend`는 최신판을 그대로 (모듈 데이터 에셋은 판마다 값이 달라 통째로 복사하지 않음).
- **움직이는 부품은 몸체의 직접 자식으로만** 둔다 (행정 관제소 깃발). 바깥 모듈 내보내기는 `bake_space_transform=True`라 자식의 자식은 축 변환이 한 번 더 들어가 90° 눕고 자리가 어긋났음(7-6과 같은 문제). 사슬처럼 이어 움직일 조각은 형제로 두고 Unity 컴포넌트가 부모 공간에서 사슬을 계산한다 (`ModuleFlutter`: `Flutter_{이름}` + `_1` · `_2`, 피벗 = 깃대 축 · 앞 조각 끝 이음선, 이음선은 2mm 겹치고 두께 · 높이를 조금씩 줄여 같은 평면을 피함).
- **움직이는 부품 이름 규칙** (StationArtBuilder가 컴포넌트를 붙임): `Spin`(회전 링) · `SpinFan*`(냉각팬) · `SpinRadar*`(레이더 초당 40°, Blender 이름은 겹칠 수 없어 `SpinRadar_{모듈}`) · `SpinDish*`(접시 안테나 초당 8°) · `Flutter_*`(깃발). 굽지 않고 공용 재질 슬롯(`Hull` · `HullDark` · `Accent`)을 쓴다 — 몸체 팔레트(`NB_*`)나 `Pipe`는 Unity 공용 재질에 없다. 몸체처럼 여러 색이 필요하면 그 부품만 따로 굽는다: `finalize(key, parts=[부품])` → `Textures/{모듈}/T_{부품}_*` · 슬롯 `Tex_{부품}` (통신 중계소 접시 = 흰 접시 · 연보라 테 · 청록 혼 끝, 끝의 형광은 Unity가 채도 높은 색에서 발광을 만든다).
- **흔들리는 판은 위에서 내려다봐서 확인한다.** 세로축으로 꺾이는 깃발은 정면에서 거의 안 움직여 보였고, 강조 재질(발광 = 색 × 0.6)이 밝으면 조각마다 다른 명암이 지워졌다 → 꺾임 26° · 강조 재질은 실제 색(밝게 보정하지 않음). 편집 모드 미리보기는 `ModuleSpinner.Step` · `ModuleFlutter.Step`을 직접 불러 프레임을 찍는다.
- **게임 조명은 따뜻하다** (해 1, 0.86, 0.66 · 주변광 갈색 · 채도 +6): 중립 회색은 갈색으로, 흰색은 베이지로 보인다. 회색으로 읽혀야 하는 재질(방사선 차폐실 콘크리트)은 조명 반대 색을 섞는다 — 선형 (0.085, 0.1, 0.135)이 게임에서 어두운 회색. 흰색도 같다 — 여객 도킹 포트 흰 지붕(0.88, 0.88, 0.86)이 모래색으로 보여 (0.62, 0.74, 0.95)로 바꾸니 밝은 회백색. 연한 하늘색(방열판 그레이박스 색 0.72, 0.82, 0.9)도 베이지 · 흰색으로 보여 채도를 올림(선형 0.3, 0.62, 1.0). Blender 미리보기만 보고 정하지 말고 Unity 렌더로 확인.
  - **해는 앞(+z) 위에서만 비친다** (방향 0, -0.53, -0.85). 좌우(±x)를 보는 면은 주변광만 받아, 어두운 색 · 금속성이 높은 재질(어두운 우주를 비춤)은 거의 검게 보였다 → 방열판 날개 금속성 0.6 → 0.15, 끝 받침틀 HullDark → Hull. 미리보기는 모듈을 90° 돌려 놓은 모습도 찍는다 (게임에서 90° 회전 배치).
- **잘게 나눈 곡면(24면 아치)을 평면 음영으로 두면 면마다 명암 띠가 져 나무 판자처럼 보인다** (방사선 차폐실 콘크리트 지붕이 갈색 판자 통처럼 보였음). 그 곡면만 부드러운 음영(`polygon.use_smooth`, 굽기 · FBX `FACE`에서 유지, Unity 법선 = Import) — 평면 음영 이웃 면과의 경계는 저절로 날카롭게 남는다.
- **오목 다각형 뚜껑은 삼각형화 전에 `bm.normal_update()`** (화살표 · 로켓 · 별 · 방사선 날개). bmesh로 막 만든 면은 법선이 0이라 `bmesh.ops.triangulate`가 홈을 메운 삼각형을 만들었다 → 여객 도킹 포트 바닥 화살표가 V자가 아니라 그림자 진 집 모양으로 보였음. `prism_xy` · `prism_x` · `poly_bm`에 넣음. 행정 관제소 별 인장 · 방사선 차폐실 문양은 메워진 쪽이 판에 붙는 안쪽 뚜껑이라 겉모습 영향 없음 (다시 내보내면 바로잡힘).
- **곡면 지붕은 높이 함수 판** `surface_slab(k, 재질, xs, zs, 윗면(x, z), 아랫면(x, z))` (여객 도킹 포트 물결 지붕). 그 아래 벽 · 유리 · 창살 · 기둥 · 끝 벽 윗선도 같은 함수(지붕 아랫면 + 2~6mm)로 맞춰 틈과 같은 평면을 피한다. 곡면 위 표식 원판은 지붕이 수평인 마루 꼭대기에, 두꺼운 받침(3cm)으로 둘레의 곡면 틈을 가린다.
- Blender 5.2에서 mp4(미리보기 영상)를 만들려면 `image_settings.media_type = 'VIDEO'`를 먼저 정해야 `file_format = 'FFMPEG'`이 받아진다. 지역 보기(local view) 중에 새로 만든 오브젝트는 `local_view_set`을 해야 화면 · 렌더에 나온다.

## 7-9. 진화 모듈 외형 (2026-10-22~, `BlenderWork/Modules_Work.blend` 텍스트 블록 `evo_builder`, 배치 줄 Blender y −20)
- **방향 (사용자 피드백, 연구 단지 시안 1 ~ 4)**: 재료 모듈을 복제하거나 재료 모양에 부품을 덧붙이지 않는다 — "연구소보다 퀄리티가 떨어짐", "기존 모델 느낌이 남고 덧붙여 난잡함". 재료의 대표 특징이 **더 강해진** 모습으로 새로 고안 (연구소 돔 · 망원경 → 투명 유리 관측 돔 + 망원경, 원자 마크 → 돔을 도는 궤도 고리, 보라 칠 → 보라 형광). 레시피 이유 문장의 설정(연구 단지 = 관측 장비 + 계산 설비)을 형태로 보여 준다 (시안 1 · 2는 계산 설비를 빠뜨려 지적받음).
- **공통 언어 (사용자 결정 "1안 + 3안")**: 밝은 흰 패널 · 유리가 많은 **매끈한** 몸체 (기본 모듈의 산업적 느낌과 대비 — 둥근 모서리 · 부드러운 음영, 배관 · 랙 · 팬 같은 산업 부품은 넣지 않음) + **단계 수만큼의 별 배지** (`evo_star_badge`, 어두운 원판 + 흰 테 + 흰 형광 별 — 개수로 구분) + **밝은 테두리 띠** (위쪽 둘레). 흰 몸체 위에 흰 형광 띠만 두면 안 보인다 → 어두운 홈 안에 띠 (시안 1 · 4 둘 다 겪음).
  - 흰 패널 = `EVO_White` 선형 (0.62, 0.74, 0.95) — 게임 조명에서 회백색 (7-7). Blender 미리보기에선 푸르게 보임.
  - 유리 두 종류: 몸체에 두른 유리 띠 = 굽는 짙은 남색 (`EVO_BandGlass`, 불투명) / 속이 보여야 하는 돔 = 굽지 않는 부품의 `FX_EvoGlass` (Unity `M_EvoGlass` 투명, `ModuleFxMaterials`).
- **매끈한 몸체는 한 덩어리 고리 잇기** `loft_body(k, 평면, [(높이, 바깥 오프셋, 구간 재질)…], 아래 뚜껑, 위 뚜껑)` — 높이마다 오프셋을 줄여 위 · 아래 모서리를 둥글게, 유리 띠 · 테두리 홈은 오프셋을 들인 구간. 면마다 재질 `add_multi` (조각을 나누면 부드러운 음영이 끊기고 사이에 뚜껑이 생김). 곡면(옆 · 둥근 모서리)만 `use_smooth`, 위 · 아래 뚜껑은 평면 → 경계는 저절로 날카로움.
- **미리보기 렌더** `bpy.app.driver_namespace['evo_preview'](이름들, 경로, yaw, pitch, dist)` — `_PrevCam` · `_PrevSun`로 EEVEE 렌더 (MCP 뷰포트 캡처가 빈 화면이었음). 새 재질이 생긴 직후 첫 렌더는 셰이더 컴파일로 빈 화면 → 한 번 더.
- **도는 부품** (몸체 직접 자식, 7-7): 돔 안 망원경 = `SpinDish_*` (굽지 않으므로 공용 슬롯 Hull · HullDark · Accent + 렌즈 FX), 궤도 고리 = `SpinOrbit_*` — **고리 + 전자를 한 덩어리로** 두고 고리 기울기 축으로 돌리면 고리는 제자리처럼 보이고 전자만 고리를 따라 달린다. 축은 Unity가 메시에서 계산 (`StationArtBuilder.OrbitAxis`: 원점 = 고리 중심, 가장 먼 점 × 가장 직각인 점) → `ModuleSpinner._axis` (모듈 루트 기준, 모듈 회전을 따라감). 고리 가장 낮은 곳이 다른 조각(돔 받침)에 닿지 않는지 기울기 · 반지름으로 계산.
  - **가져온 메시는 Read/Write가 꺼져 있으면 에디터에서도 `AcquireReadOnlyMeshData`가 예외** ("Not allowed to access vertex data") → `SpinOrbit` 부품이 있는 모델은 조립기가 가져오기 설정 Read/Write를 켬.
- 투명 유리 돔은 알파를 낮게 (`M_EvoGlass` 0.12) — 농장 유리 값(0.24 + 발광)은 겉 · 속 껍데기가 겹쳐 우윳빛으로 뿌옇고 속 망원경이 가려졌음.
- 편집 모드 렌더(멀리 떨어진 곳 + URP 카메라 후처리)에서는 흰 몸체가 베이지로 보인다 — 여객 도킹 포트 흰 지붕도 같은 톤이므로 같은 조건끼리 비교해 판단.
- **Unity 적용**: `RecipeSetup`이 `SM_Evo_{Id}.fbx`가 있으면 그레이박스 칸 상자 대신 모델(`StationArtBuilder.AttachModel`) — 칸 판정 · 선택 콜라이더는 칸마다 그대로, 통로 깊이는 `ConnectorDepthBaker.Measure`. 진화 모듈에 `StationArtBuilder.Rebuild`(모듈 하나 = 콜라이더 상자 하나)를 쓰지 않는다 (ㄱ자 · 고리 모양이 큰 상자로 뭉개짐).
- 밸런스 봇 측정이 에디터에서 도는 중에는 `finalize` 전에 `NB['ns']['UNITY_MODELS']`를 작업 폴더로 바꿔 굽기 · 내보내기만 하고, 측정 뒤 프로젝트로 복사 (프로젝트에 쓰면 자동 가져오기 · 새 재질 코드 컴파일이 측정을 끊을 수 있음).
- **색감 (사용자 2026-10-22 "너무 흰색만 있어 보임")**: 포인트 부품(고리 · 뚜껑 · 끝판 · 띠)은 모듈 색 `EVO_Tint_*`, 받침 옆면(테두리 띠 아래)은 짙은 모듈 색 `EVO_Tint2_*` (`tint="both"`). 모듈 색 = 게임 UI 색이 기본이지만 흰 몸체와 비슷하면(강철 회색 · 세이지 · 노랑) 같은 계열을 짙게, 내용물과 어긋나면 맞춤 (융합 발전소 = 남색, 중력 거주구 = 거주 계열 주황 — 사용자 선택).
- **실내가 있을 수 있는 형태 (사용자 지적 2026-10-22)**: 진화 모듈도 고유 내부 템플릿(Phase 11, 바깥 실루엣을 키운 방)을 만든다 → 받침 위에 장비만 늘어놓지 않는다. 주된 덩어리 = 벽 · 지붕 · 유리로 감싼 홀 (바닥 = 받침 위, 높이 0.3 안팎 이상), 장비는 그 안(유리 고창 · 천창 너머로 보이게)이나 지붕 위. 융합 발전소 · 수소 플랜트 · 태양광 어레이 · 축전 뱅크 · 자재 재생 플랜트를 이 규칙으로 다시 만듦 (v2).
- **움직이는 부품 이름 꼬리**: Blender 오브젝트 이름은 파일 안에서 겹칠 수 없어, 기본 모듈이 쓰는 이름에는 꼬리를 붙인다 — 실드 발생기 `Emitter_{이름}` + `EmitterRingA_{이름}` · `EmitterRingB_{이름}` · `EmitterCore_{이름}` (조립기가 같은 꼬리끼리 실드 연출 연결), 포탑 머리 `Head_{이름}` (운석 요격이 `Head` · `Head_*` 모두 돌리고 가까운 포구에서 쏨 — 포구 = 피벗에서 +z 0.4, 돌아도 칸 밖으로 안 나가게), 태양 패널판 `SunPanel_*`. 여러 색이 필요한 도는 부품(중력 거주구 링 · 포탑 머리)은 `finalize(key, parts={부품: 텍스처 이름})`로 따로 굽는다 (`Tex_{이름}` 슬롯, 텍스처는 같은 폴더 — `ModuleTextureMaterials.EnsureAll`이 폴더의 텍스처를 모두 연결).
- **움직이는 부품의 `Fx_` 자식 = 손자 오브젝트 (2026-10-26 사용자 발견 — 식량 공장 드럼 유리 커버가 누워 보임)**: `finalize`는 도는 부품의 유리 · 빛 · 반짝임을 부품 아래 `Fx_{이름}` 자식으로 떼어 내는데(재질 · 그림자 분리), 7-6과 같은 `bake_space_transform=True` 문제로 이 손자에 축 변환이 한 번 더 들어가 **X 90° + 위치 밀림**(부품 위치를 X 90° 돌린 만큼)으로 들어온다. 1 · 2단계 20개 전부 해당 (중력 거주구 링 · 드럼 · 드론 쇼 · 회전목마 · 열차 · 등대 렌즈 빛줄기 · 포탑 머리 등). → Unity `StationArtBuilder.PlaceModel`이 부품 아래 `Fx_*`를 부품 기준 제자리(위치 0 · 회전 0 · 크기 1)로 되돌림. 부품 메시와 같은 원점 · 축으로 굽힌 자식이라 항상 맞음. Blender 쪽은 그대로 (다시 내보내도 같음) — 손자에 다른 변환이 필요한 부품은 만들지 말 것.
- **연출 면 ↔ 몸체 면 같은 평면 (2026-10-27 사용자 발견 — 1단계 뚜껑 · 중력 거주구 위 · 융합 발전소 바닥이 일렁거림)**: `evo_builder`가 유리 · 창 · 형광 빛줄 · 반짝임(`Emblem_Fx_*`, 부품 아래 `Fx_*`)을 몸체 면과 같은 평면(0mm)에 겹쳐 둔 곳이 진화 모델 거의 전부에 수천 개 있었음 (투명 유리는 깊이를 안 써서 같은 깊이의 불투명 몸체와 화소마다 경쟁 → 카메라가 움직이면 깜빡임). → Unity 가져오기 후처리 `EvoFxDepthOffset`이 같은 평면(0.3mm 안)에서 넓이 있게 겹친 삼각형 짝을 찾아, 우선순위가 높은 쪽(반짝임 > 투명 > 그 밖 연출 > 몸체)을 평평한 덩어리째 법선 방향으로 1.7mm × 순위 차이만큼 띄우고, 띄운 면이 다른 층에 새로 걸리면 거리를 바꿔 되풀이 (등을 맞댄 불투명 면끼리는 그대로). 남는 것은 0.05 ~ 0.3mm 떨어진 근접 짝뿐 (32비트 깊이라 안 깜빡임). **앞으로 Blender에서 연출 면은 몸체 면에서 2mm 이상 띄워 만든다** (후처리는 안전망).
- **멈춘 입자로 구운 연출 → Unity 움직이는 연출 (2026-10-27 사용자 플레이 점검)**: 열차 별 연기 · 정련 콤비나트 불꽃 분수 · 드론 정비창 드론 무리(잇는 빛줄 포함)는 Unity가 입자로 다시 그리고(`SparkEmitterFx` · `DroneShowFx`), 구운 것은 같은 가져오기 후처리에서 지운다 (`EvoBakedFxStrip` — 모델 · 오브젝트 · 재질 · 범위 규칙). Blender 원본과 미리보기는 그대로. **이 연출의 위치를 Blender에서 옮기면 규칙 범위와 `StationArtBuilder.PlaceModel`의 방출구 위치도 맞춘다.** 앞으로 Unity가 움직일 연출은 Blender에서 굽지 말고 위치 표시만 남긴다.
- **구운 본체에서 움직일 조각 떼어 내기 (2026-10-27, 치안 본부 순찰차 · 화물 환적장 보트)**: 확정(finalize)된 본체 메시에서 조각(꼭짓점으로 이어진 섬)의 중심이 대상 상자 안인 것만 골라 새 부품으로 옮기면 본체 텍스처 UV가 그대로라 **다시 굽지 않아도 된다** (부품 재질 = 본체 `Tex_` 슬롯 공유). 주의: ① 회전한 상자 조각은 축 정렬 크기가 커지므로(기울어진 보트 0.105 → 0.124) 크기 기준을 넉넉히, ② 원형 테 · 고리 조각은 중심이 가운데 축에 있어 상자 안으로 잡히므로 크기 기준으로 뺀다, ③ 근처 같은 재질 조각(물길 테 전구)은 위치를 계산해 빼고 고른다. 순찰차는 `build_security_hq`가 다음부터 부품으로 만들고(확정 때 parts에 차 둘 추가), 환적장은 확정 뒤 `cargo_flume_split()`을 부른다.
- **가는 조각 굽기 = 재질 색 칸 (사용자 지적 2026-10-23 시민 회관 → `tex_builder` 수정)**: 몸체는 모듈 전체를 텍스처 한 장(1024)에 굽기 때문에, UV에서 칸 중심을 못 받는 가는 면(창 사이 6mm 은빛 살 · 나무 잎 · 5~9mm 기둥 · 줄기)은 이웃 섬 여백 색이 묻어 같은 조각끼리 색이 들쭉날쭉했다 (대형 토러스 잎이 검게, 기둥이 검게). → `bake_object`가 UV를 조금 줄여 텍스처 맨 위에 재질별 색 칸(`PAL_CELL` 16px)을 비우고, 칸 중심을 `PAL_MIN`(3)개 못 받는 면은 자기 재질 칸 한 점을 가리키게, 굽고 나서 칸을 같은 재질의 덮인 면 평균(색 · AO · 거칠기 · 금속)으로 채움 (`_palette_prepare` · `_palette_fill`, 원본 = 텍스트 `tex_builder_backup_1023`). 2단계 6종을 이 방식으로 다시 구움. 1단계 24종은 같은 모양끼리 색이 갈린 곳이 없어 그대로 (다시 확정할 때 저절로 적용).
  - 검사: 구운 몸체에서 섬(꼭짓점 공유)마다 칸 수 · 크기 · 색을 재고, 같은 모양 무리의 밝기 편차를 본다 (나무 잎 Leaf · Leaf2처럼 일부러 두 색을 섞은 무리는 편차가 두 색 차이로 일정하면 정상).
- **표식은 밝기 차이로 (사용자 지적 2026-10-23)**: 창 줄 사이 분홍 십자를 흰 판 위에 두니 판과 밝기가 비슷해 안 보였음 → 어두운 판 위 빛나는 표식, 칸 폭에 꽉 차게 (색약 배려 — 색만으로 구분하지 않음). 창 · 표식은 면(직선 변)마다 같은 간격 홀수 칸, 표식은 면 가운데 기준 대칭.
- **반짝이는 점 (별빛 · 신호등)**: 재질 `FX_TwinkleWhite` · `FX_TwinklePurple` (Unity `SpaceStation/Twinkle`) + `twinkle_phase(obj, seed)` — 이어진 점마다 무작위 위상을 꼭짓점 색 R에 넣음 (FBX가 색을 같이 내보냄). 밝기만 바뀜.
- **굽지 않는 부품의 n각형은 내보내기 전에 삼각형으로**: 돔 바닥 메움(`holes_fill`) · 큰 평면 뚜껑 같은 5각 이상 면을 Unity가 "self-intersecting polygon … discarded"로 버림 → 부품(FX · 도는 부품)도 n각형을 미리 나눈다 (`finalize`는 굽는 몸체만 나눔). 2026-10-22 진화 모듈 23종 일괄 처리.
- **자연 현상 효과는 얇은 판으로 굽지 않는다 (사용자 지적 2026-11-02 오로라 "칼로 자른 것처럼", 은하수 "오염된 물")**: 얇은 판은 UV가 없으면 끝을 흐릴 수 없고 주름 옆선이 칼날처럼 보이며, 자리가 고정된다 → 슬롯을 비우고 Unity가 UV 있는 촘촘한 메시를 만들어 (`AuroraFx`) 셰이더로 사방 끝 · 시선과 나란한 옆선을 흐리고 위치를 떠돌게 한다. 물 표면은 불투명 윗면 한 장에 셰이더로 그림 (`MilkyRiver` — 속에 구운 빛줄 · 별 상자는 가려지게 되므로 그대로 둬도 됨, 슬롯이 다른 모듈과 공유면 `StationArtBuilder.FxOverrides`로 이 모델만 바꿈). 너울 위 좁은 반사는 고리 줄을 그리므로 하늘은 흐린 단계로, 햇빛은 넓은 빛 길 안의 잔 반짝임으로.

  - 3단계 → 지구급 상징 모듈로 이어짐 (사용자 2026-10-27): 3단계의 프리즘 기술이 상징 모듈에서는 **태양과 같은 역할**을 하게 만든다 (예: 프리즘이 모은 빛이 정거장을 비추는 작은 해).

  - "너무 놀이기구 같은" 형태는 이상하게 느껴짐 (거울 바이킹 시안 탈락) — 놀이기구를 그대로 옮기지 말고, 모듈 기능이 볼거리 · 쉼터가 된 모습으로.
- **2단계 이상 내부 아이디어 — 우주복을 입고 걷는 개방형 정원** (Phase 11 진화 모듈 내부 템플릿 때 적용):
  - 2단계부터는 완전히 꽃핀 미래 기술로 **우주의 압력에서 자유로운 우주복**이 보편화된 설정. 주민(동물)은 그 우주복을 입고 유리 지붕 밖 **실제 정원 · 광장을 돌아다닌다** → 실내 방에 갇힌 느낌 없이 자연스러운 개방감.
  - 내부 템플릿 = 닫힌 방만이 아니라, 바깥 모형의 열린 정원 · 산책로 · 전망 데크도 걸어 다니는 공간. 실내(홀)와 바깥(정원)을 오가는 구성.
  - 기본 · 1단계 내부는 지금처럼 닫힌 실내 (테마 차이: 생존 · 첨단 기술 → 여가).
  - **살아 있는 식물은 2단계에서도 유리 안** (사용자 결정 2026-10-26): 기술이 발달해도 우주복이 없는 생명체는 2단계 수준에서 바깥 생존이 힘들다는 설정. 바깥 정원 = 빛 꽃 · 거울 · 금속 · 수정 같은 기술 식물, 살아 있는 식물은 유리 돔 · 온실 · 유리 덮개 화분 속.
  - 나중 (3단계 모듈 · 지구급 상징 모듈): 생명체를 바깥에서 보호하는 미래 기술 모듈을 고려 → 살아 있는 식물 · 동물을 유리 없이 두는 자유도를 높임 (사용자 바람).
  - **3단계 내부 (사용자 결정 2026-11-10)**: 바깥 정원은 **우주복 없이 맨몸**, 살아 있는 나무 · 꽃 · 동물도 **유리 덮개 없이** 바깥에 (생명 보호 기술 완성). **모듈마다 직접 체험 하나 + 정말 간단한 미니게임** (예: 궤도 항만 = 가리비 배 경주, 궤도 도시 = 궤도열차를 정거장에 정확히 멈추기). 순서 = 외형 순서 (궤도 도시부터), 3단계 진주 · 금 키트는 궤도 도시 때 같이.
- **2단계 플레이어 직접 체험 8가지 (사용자 2026-11-02)** — 아래 8종은 내부 템플릿에서 플레이어가 직접 타거나 들어가 체험한다. 다른 2단계 모듈은 정원 · 전시관 구성. 외형의 해당 부품이 체험의 뼈대이므로 내부도 그 모양을 키워 쓴다:

  |---|---|---|
  | 대형 토러스 | 기차 탑승 관람 | 은하철도 링 (도는 밤 열차 · 별빛 고가 선로 · 유리 지붕 역 넷) |
  | 연구원 | 미로 체험 | 별빛 데이터 미로 (서버 랙 벽 세 겹 · 막다른 길 · 바닥 길잡이 점 → 가운데 유리 연구실) |

  | 화물 환적장 | 후룸라이드 탑승 체험 | 은하수 후룸라이드 (아래 코스) |
