# 모델링 02 — 공간 구성 (문 자리 예약 · 벽 뚫림 · 콘솔 방향 · 열리는 면 · 화면 · 톱니 · 장비 특징)

> 원래 `MODELING.md` 7절 (72 ~ 95줄)을 그대로 옮김 (2026-11-11 분할). 매번 확인할 항목은 [00-checklist.md](00-checklist.md).

## 7. 공간 구성
- **창 너머로 보이는 빈 공간에는 바닥이나 배경을 둔다** (코어 가운데 뜰 바닥 — 없으면 아래 매단 모듈이 떠 보임).
- 연결 통로·로비가 이동 경로를 가로막지 않는지 확인 (코어 모서리의 쐐기 벽이 진입을 막았음 → 사각 로비).
- 해치(수직 문 자리)는 창틀·벽에서 떨어뜨린다 (`InteriorSocket.Offset`, 코어는 바깥 모서리 쪽 1.2).
- **문 자리 앞 예약 구역에 소품을 두지 않는다.** 빌더가 문 자리마다 끼우는 키트 문 패널·막힌 벽은 폭 3.2(가로 ±1.6)에 벽면에서 방 안쪽으로 약 0.2~0.25 튀어나온다 → 수평 문 자리마다 **가로 ±1.7, 벽면에서 안쪽 0.45, 높이 F ~ F + 3.75** 안은 비운다. 실제 사례: 채굴 도킹 벤치 끝이 뒤 문틀 기둥 속에 0.2 들어감, 의료실 침대 모서리·수액 거치대가 옆·앞 문틀에 닿음. 검사: `overlap_check.door_zone(이름들, 문 자리 목록)` → 빈 목록이어야 함.
- **소품이 벽을 뚫고 나가지 않게 한다.** 회전하는 소품(드론 팔·날개 등)은 가장 멀리 뻗는 방향의 끝까지 재서 벽 안에 두고, 벽에 붙이는 소품도 0.03 이하만 묻는다. 실제 사례: 정비 베이 드론 팔을 눈 방향과 함께 돌려 벽 쪽으로 곧게 뻗게 해 날개가 0.11 뚫고 나감. 검사: `overlap_check.wall_poke(이름, x0, x1, z0, z1, ceil=천장)` → 빈 목록 (상자형 방).
- **기울인 콘솔·화면은 사람이 서는 쪽을 향하는지 확인한다.** `obox`의 `rx`는 로컬 +z 끝을 위(음수)/아래(양수)로 기울이고 화면 법선은 `(0, cos, sin(rx))` 쪽 → 벽이 +z면 `rx` 음수, 벽이 −z면 `rx` 양수. 다른 모듈의 콘솔 코드를 복사할 때 벽 방향이 반대면 부호도 반대로. 실제 사례: 채굴 도킹(벽 +z) 콘솔을 제련소(벽 −z)에 그대로 써서 화면이 벽을 봄.
- **열리는 면(캐비닛·랙 앞면, 문짝, 서랍) 앞은 0.8 이상 비운다.** 구석에 ㄱ자로 붙이면 안쪽 것의 앞면이 옆 것에 막힌다. 실제 사례: 연구소 서버 랙 3대를 구석에 ㄱ자로 둬 안쪽 랙 앞이 옆 랙에 5cm로 막힘 → 한 벽을 따라 한 줄로.
- **화면 재질(`Screen`·`ScreenDark`)은 화면에만.** 유리창·덮개에 쓰면 청록 모니터처럼 보인다 (장갑 격벽 소화기함 창). 안이 보여야 하면 앞을 트고 내용물을 넣는다.
- **화면은 "빛나는 판"으로 끝내지 않는다.** 바탕은 어두운 화면색(`ScreenDark`), 그 위에 밝은 요소(`Screen`)로 제목줄·그래프·게이지·글자 줄을 0.003 띄워 올리고, 경고 강조는 다른 색(`Molten` 등)으로.
- **맞물려 도는 톱니는 회전 전 구간을 계산으로 검사한다.** 직사각 톱니는 폭이 피치의 0.4를 넘으면 돌다가 서로 겹침(포탑 폭 0.07 / 피치 0.17 → 겹침, 0.05 → 0). 톱니 끝은 상대 허브·원판 반지름보다 짧게, 속도비 = 톱니 수 비(반대 방향), 시작 위상은 상대 톱니 사이 빈칸이 맞물림 점을 향하게(피니언 반 피치 위상).
- **움직이는 장식은 별도 오브젝트로 내보내고 Unity 컴포넌트로 돌린다** (`InteriorOrbit`: 템플릿 로컬 중심·축·속도, `InteriorTemplateBuilder`의 `OrbitSpec`으로 붙임). 회전은 매 프레임 누적(RotateAround)하지 말고 처음 로컬 위치·회전에 누적 각도를 한 번에 적용 — 내부 공간이 y −5000이라 월드 좌표 누적 오차로 위성이 궤도를 벗어났음.
- **장비는 "그 물건만의 특징"을 넣는다.** 같은 크기 칸 + 손잡이는 무엇이든 서랍장으로 보임(연구소 서버 랙) → 서버 랙은 장착 구멍 기둥 + 얇은 장비(통풍 슬릿·LED·드라이브 베이), 손잡이 없음. 새 장비를 만들 때 실물 사진에서 알아보게 하는 요소 2~3개를 먼저 정한다.
- **같은 평면을 피하려고 배치를 어긋나게 하지 않는다.** 쌓는 물건(컨테이너·상자)은 실물처럼 모서리를 맞추고, 겹침은 위아래 사이 아주 작은 틈(모서리 돌출 + 0.002)으로 피한다. 실제 사례: 화물 터미널 2단 컨테이너를 0.3 비켜 쌓아 틀어져 보였음.
- **이미 만든 소품 모양은 다시 쓴다.** 공구·의자·화면 같은 소품은 앞서 피드백을 받아 다듬은 함수(정비 베이 `wrench`·`screwdriver`·`hammer`·`pliers` 등)를 가져다 쓴다. 새로 대충 만들면 같은 피드백이 반복된다 (손상 통제실 공구가 막대 + 상자로 돌아감).
- **나란한 같은 가구(사물함 칸 등)는 몸통 하나 + 칸마다 문.** 상자를 칸마다 조금씩 띄우면 틈으로 뒤가 점선처럼 비친다. 맨 끝 칸도 다른 칸과 같은 디테일 (막는 판만 밋밋하면 어색).
- **작은 소품도 실루엣이 읽히게.** 공구·장비를 막대 + 상자로 끝내지 않는다: 손잡이(그립 홈·고무 피복 색)·쇠 부분·특징 형태(스패너 입·고리, 망치 노루발, 펜치 축, 드릴 척·배터리) 2~4개 부품으로 "무엇인지" 보이게.
- **키트 조각이 문 패널(폭 ±1.6, 벽면에서 0.4) 밖으로 나오지 않게 한다.** 통로 이음 고리(반지름 1.87)를 벽면 중심에 둬 절반이 방 안으로 나와 문 패널 옆에 어두운 다각형으로 보였음 → 통로 쪽으로 반 두께 + 0.003 밀어 벽 속에. 고리를 치우자 그 뒤에 가려 있던 열린 문짝 끝(1.72)이 드러남 → 열림 거리 = 패널 반 폭 − 문짝 폭 − 0.04. **조각을 옮기거나 지우면 그 뒤에 가려 있던 것까지 다시 본다.**
- **문 자리 옆 벽에 붙은 장비의 면 디테일은 벽에서 0.5 이상 떨어뜨린다.** 키트 문 패널(열린 문·막힌 벽 모두)이 벽면에서 0.4 튀어나와, 그 옆 장비 면의 벽 쪽 0.45 띠는 패널 옆면에 가려진다. 실제 사례: 태양광 인버터 차단기 3번째(벽에서 0.14)가 패널 옆면에 파묻혀 보임. 6.4m 방(벽 ±3.2)이면 디테일 좌표 |값| ≤ 2.68. **그렇다고 2.68 ~ 벽 사이를 비워 두지 않는다** — 장비 틀이 벽까지 뻗으면 그 띠는 닫힌 면(수납함·옆판)으로 채운다 (포탑 탄약 랙 오른쪽 0.5가 윗판 아래 빈 칸으로 보였음).
- **빛나는 요소는 "무엇을 알리는지" 읽히게 둔다.** 같은 물건 여럿 중 일부만 발광 재질로 칠하면 고장(꺼진 것)처럼 보인다 (포탑 포탄 뇌관). 상태는 물건마다가 아니라 칸·장비마다 표시등 하나로, 다른 소품에 가리지 않는 자리에. 모서리 장비는 통로 조명이 닿는지 확인하고 어두우면 앞에 약한 조명.
- **그림·도식은 실물과 같은 방향으로.** 태양을 향하는 패널은 면이 태양을 보도록 태양 쪽 가장자리가 낮다 — 태양광 점검 화면에 반대로(태양 쪽이 높게) 그려 천장 너머 실제 패널과 어긋났음.
- **창(시선이 모이는 벽) 아래·앞에 두는 가구는 그 벽면과 나란히 놓는다.** 비스듬한 벽(깎인 모서리 등)의 창 아래에 x·z 축에 맞춘 가구를 두면 벽과 어긋난 각도가 눈에 띈다 (산소 생성기 모서리 창 아래 콘솔·사물함). 가구는 "벽 기준 로컬 좌표"(+z = 벽 쪽, +x = 벽을 따라)로 만들고 벽 법선에 맞춰 돌려 놓는다. 창 아래 가구 윗면은 창턱 아래로, 창턱(벽에서 0.16) 앞으로 0.05 이상 띄운다 (사물함 F + 1.7이 창턱 F + 1.69~1.74에 박혀 보였음).
- **방 둘레 강조 띠·몰딩은 문 자리에서 잘라낸다** (키트 패널이 F + 3.8까지 차지). 채굴 도킹 첫 버전은 F + 3.2 띠가 문 패널을 가로질렀음.
